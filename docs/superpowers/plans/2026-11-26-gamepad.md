# Геймпад под «Steam Deck Verified» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Забег и все экраны игры проходятся одним геймпадом: стик — движение, A/RT — кусь, B/LT — язык, Start — пауза, Select — звук; крестовина ходит по кнопкам меню, LB/RB листают ряды выбора; значки кнопок на экране.

**Architecture:** Новый файл `src/js/14-gamepad.js` раз в кадр опрашивает Gamepad API (`navigator.getGamepads()`, раскладка `standard`). В забеге он пишет в те же `stick` и `input`, что экранный джойстик и клавиатура; в окнах ведёт фокус по кнопкам страницы «ближайшая в сторону нажатия» и нажимает их `click()`. Режим геймпада — флаг `padMode` и класс `pad` на `<body>`, как `touchMode`/`touch`; CSS по классу меняет подписи и рамку фокуса.

**Tech Stack:** ванильный JS одним блоком (`tools/build.mjs`), Gamepad API, CSS; тесты на playwright-core с подменой `navigator.getGamepads`.

**Spec:** `docs/superpowers/specs/2026-11-26-gamepad-design.md`

## Global Constraints

- База: `main` **после слияния ветки `sugar-economy`** (решение Сеймура). В меню тогда шесть рядов выбора `.pr` (`#sw` вкусы, `#skins`, `#hats`, `#eyes` и следующие ряды гардероба), закрытые элементы — `button.lock`, выбранный — `aria-checked="true"`; на итоговой карточке есть `#chestAgain`.
- Раскладка `standard`: A=0, B=1, LB=4, RB=5, LT=6, RT=7, Select=8, Start=9, крестовина 12 вверх, 13 вниз, 14 влево, 15 вправо; левый стик — оси 0, 1.
- Мёртвая зона стика 0,18 по модулю наклона, дальше сила `(m - 0.18) / 0.82`; курки нажаты при `value > 0.5`.
- A/RT — кусь: укус в кадр нажатия, удержание = `input.dashHeld` (новый укус после каждой перезарядки), одно нажатие не даёт двух укусов в одном кадре. B/LT — язык (`input.dodge`) по нажатию. Start — пауза/продолжить. Select — `toggleMute()`.
- Отпущенный стик (в мёртвой зоне) — `stick.mag = 0`, конфета тормозит.
- В окнах: крестовина или стик — фокус на ближайшую кнопку в сторону нажатия; повтор при удержании: первый через 0,4 с, дальше каждые 0,12 с; A — `click()` по кнопке в фокусе; B — назад: закрыть альбом, паузу (продолжить), итоговую карточку (как `#overX`), иначе ничего; LB/RB — предыдущий/следующий **открытый** элемент ряда `.pr`, в котором фокус, иначе ряда вкусов `#sw`.
- Навигация пропускает `#nick` (поле имени) и `#pAdmin`; кандидаты — видимые, не `disabled` `button`, `[role=radio]`, `a[href]` внутри верхнего открытого окна.
- Первый фокус экрана: меню — `#play`, пауза — `#resume`, итоговая карточка — `#again`, альбом — `#albumX`.
- Режим геймпада включает любой ввод с геймпада (кнопка или стик вне мёртвой зоны); движение мыши, клавиша или касание выключают его. Рамка фокуса и значки — только в режиме геймпада. В режиме геймпада мышь не тянет конфету.
- Отключение геймпада (`gamepaddisconnected`) в забеге ставит паузу.
- Значки в стиле Xbox: A, B, LB, RB, ☰; рисуются CSS (кружок с буквой), без картинок.
- В режиме геймпада текст страницы не мельче 12 px; холст не трогаем.
- Звук на сайте по-прежнему включается первым кликом, касанием или клавишей; геймпад его не включает.
- Весь новый текст через `t()` на двух языках; синтаксис и CSS не новее iOS 15; одна страница без внешних скриптов; движение от `dt`.
- Каждая задача заканчивается своими тестами (`npm run build && node tests/run.mjs pad`) и коммитом `src/` с собранным `index.html` в ветку `gamepad`. Полный `npm test` — один раз, перед пушем.

## Review Focus

- Два геймпада сразу (Deck и подключённый внешний): берётся первый с `mapping === 'standard'`, второй не дёргает фокус и конфету.
- Окно открылось поверх другого (альбом поверх меню, пауза поверх забега, итоги после смерти): фокус переходит в верхнее окно, а не остаётся на кнопке под ним.
- Фокус на кнопке, которая пропала (раздел свернулся, покупка заменила кнопку, карточка перерисовалась): следующее нажатие крестовины ставит фокус на первую кнопку экрана, а не «в никуда».
- Кнопка A нажата в меню и ещё держится, когда начинается забег: не даёт укуса в первом кадре (нажатие засчитано меню).
- Геймпад «залип» с наклоном стика (дрейф около 0,1): режим геймпада не включается и не перехватывает мышь, пока наклон в мёртвой зоне.

  // axes = [0.1, 0.05] → k.stick.mag === 0; через 60 кадров скорость конфеты < 20% прежней
  // axes = [0.1, 0] с самого начала (дрейф) на свежей странице → режим геймпада не включился
test('gamepad: A bites once on a press and again only after the cooldown; B tongues; Start pauses; Select mutes', ...)

  // держать A 1,5 с → начал рывков столько же, сколько при input.dashHeld = true в touchMode за 1,5 с (±1)
  // RT value 0.8 работает как A; press(1) → input.dodge было true в этом кадре (или язык выпущен); LT 0.8 как B
  // press(9) → пауза открыта; ещё press(9) → закрыта; press(8) → Sfx.on переключился
  // A, зажатая в меню до startGame, не даёт рывка в первом кадре забега
test('gamepad: a mouse move or a key hands control back; a disconnect pauses the run', ...)
  // режим геймпада, затем mousemove → класс pad снят; затем keydown 'Space' — тоже снимает
  // в режиме геймпада mousemove не меняет input.sx (конфета не тянется к курсору)
  // dispatchEvent(new Event('gamepaddisconnected')) в забеге → пауза открыта
test('gamepad: with two pads only the first standard one drives', ...)
  // getGamepads → [null, {mapping:'', ...наклон вправо}, {mapping:'standard', ...наклон влево}] → stick.vx ≈ -1
